## 1. 背景と課題

AIエージェントの業務導入が急速に進む中、日本企業や官公庁、金融・製造・重要インフラの現場において、最大の障壁となっているのが**「社内機密情報・ソースコード・個人情報の漏洩リスク」**です。

一般的なクラウド型AIツールや無制限自律エージェントには、以下の深刻なリスクが存在します：

1. **外部クラウドへの重要ソースコード・プロンプトの送信**: 社外APIサーバーへ送信されることによる意図せぬ情報漏洩や学習データへの取り込み懸念。
2. **エージェントによるローカル環境の機密ファイル窃取**: 隔離されていないエージェントが、端末内の `.env` ファイル、SSH秘密鍵（`id_rsa`）、クラウド認証情報（`~/.aws/credentials`）を勝手に読み取り、外部へ送信してしまうリスク。
3. **プロンプトインジェクション（Prompt Injection）**: 悪意ある入力やWebページ上の隠しテキストにより、エージェントが指示を上書きされ、社内データを外部送信させられる脆弱性。
4. **個人情報（マイナンバー、クレジットカード番号等）の混入**: 開発・テストデータやログの中に顧客の個人情報が混入し、監査不能な形でモデルに渡されるリスク。
5. **事後検証・証跡の欠如**: 「AIが具体的に何を実行し、どのファイルにアクセスしたか」を法務や監査部門に証明できないブラックボックス性。

**Naikaku AI Togo System** は、これらの課題を抜本的に解決するため、**「情報漏洩防止（Data Loss Prevention: DLP）」**を中核に据えた7重の多層防護（Defense in Depth）アーキテクチャを採用しています。

         │

 │ 第4層: リアルタイムDLPサニタイザー (自動検出＆暗号マスキング)   │ ── APIキー・マイナンバー・クレカ自動除去

---

### 第1層: ゼロ外部送信・完全オフライン隔離（Ollama / Local LLM ネイティブ対応）

Naikaku は、本機上で動作するオープンソース LLM（**Ollama**）を第一級のプロバイダとして完全ネイティブサポートしています。

- **社外ネットワークへのパケット送信ゼロ**: インターネットから物理的に切り離されたクローズドネットワーク（Air-Gapped 環境）や、社内オンプレミス環境でも 100% 完結して自律目標達成（`/goal`）を実行できます。
- **APIキー不要・従量課金ゼロ**: トークン流出や高額請求のリスクが原理的に存在しません。
- **モデル選択の自由**: `Qwen 2.5-Coder`、`Llama 3`、`DeepSeek` など、用途や機密レベルに応じたオープンソースモデルを自在に選択できます。

```bash
# 完全オフライン環境での自律実行
naikaku goal "社内認証ミドルウェアの実装とテスト" --provider ollama
```

---

### 第2層: 環境変数エイリアス隔離（Zero-Raw-Secret 原則）

外部 API（OpenAI, Anthropic 等）を使用する場合でも、Naikaku は**「生キーを UI やブラウザストレージに保存しない」**設計を徹底しています。

- Web ブラウザやクライアントの LocalStorage、Cookie に生の API キーを保存しません。
- サーバー環境変数名（例: `NAIKAKU_OPENAI_API_KEY`）をエイリアスとして登録し、ローカルゲートウェイ経由でのみ最小限の参照を行います。
- セッションが終了するとメモリ上のキャッシュは安全に破棄されます。

---

### 第3層: ロール別データアクセス制御（Data Classification Matrix）

Naikaku では、取り扱うデータを以下の 6 つのセキュリティ階層に分類し、各ロール（閣僚）ごとに厳密なアクセス許可境界を定義しています：

| 機密区分 | 名称 | 説明 | 既定の取り扱い |
| :--- | :--- | :--- | :--- |
| `public` | 公開情報 | 外部公開可能なドキュメントや仕様 | 全ロール参照可能 |
| `internal` | 社内限定 | 社内共有コード、非公開リポジトリ | 計画・実行ロール参照可能 |
| `confidential` | 機密情報 | 設計機密、ビジネスロジック | 許可された実行ロールのみ・要承認 |
| `secret` | 秘密情報 | トークン、秘密鍵、データベース接続文字列 | **外部モデル送信禁止（Local-Only）** |
| `personal-data` | 個人情報 | 氏名、連絡先、マイナンバー等 | **外部モデル送信禁止（自動マスキング）** |
| `customer-data` | 顧客データ | 顧客の取引データ、機密ログ | **外部モデル送信禁止（Local-Only）** |

`dataAccessPolicy.ts` により、機密レベルを超えるデータが外部プロバイダへ渡される前に、自動的に遮断またはマスキングが行われます。

### 第4層: リアルタイムDLPサニタイザー（自動検出＆暗号マスキング）

エンジン内部に組み込まれた DLP（Data Loss Prevention）モジュール（`dataLeakProtection.ts`）が、プロンプト、コマンド、コード、テスト出力、Git Diff を常時スキャンし、秘密情報や個人情報を検知した瞬間に強制マスキングします。

#### 検知・自動除去対象：
1. **クラウド・サービス認証情報**:
   - AWS Access Key (`AKIA...`) ➔ `[REDACTED_AWS_ACCESS_KEY]`
   - GitHub Personal Access Token (`ghp_...`, `github_pat_...`) ➔ `[REDACTED_GITHUB_TOKEN]`
   - Google Cloud API Key (`AIza...`) ➔ `[REDACTED_GOOGLE_API_KEY]`
   - JWT トークン (`eyJ...`) ➔ `[REDACTED_JWT_TOKEN]`
   - RSA / EC / OpenSSH 秘密鍵ブロック ➔ `[REDACTED_PRIVATE_KEY_BLOCK]`
   - コード内のハードコード秘密情報（`password = "..."`, `secret = "..."`） ➔ `[REDACTED_HARDCODED_SECRET]`
2. **日本固有の個人情報・識別子**:
   - **マイナンバー（個人番号・12桁）** ➔ `[REDACTED_MY_NUMBER]`
   - **クレジットカード番号（Visa, Mastercard, JCB, Amex 等）** ➔ `[REDACTED_CREDIT_CARD]`
   - **日本の電話番号（市外局番・携帯電話）** ➔ `[REDACTED_PHONE_NUMBER]`
3. **重要システムファイルへのアクセス試行**:
   - `.env`, `.env.local`, `.ssh/id_rsa`, `.aws/credentials`, `/etc/passwd` 等 ➔ `[REDACTED_SYSTEM_SECRET_FILE]`

### 第5層: 隔離作業ツリー（Worktree Sandbox）とパストラバーサル脱出遮断

AI がコードを編集する際、ホストOSのファイルシステム全体を触らせることは絶対にありません。

- **サンドボックス隔離**: Git の別ブランチまたは独立した隔離ディレクトリ（Worktree）内のみで作業を実行。
- **パストラバーサル（`../../` 脱出）の完全防止**: `validateWorktreeSafeBoundary` により、上位階層（ホストの `/`、`~/.ssh`、`~/.aws`、`/etc` 等）へのパス指定は物理的に即時遮断されます。
- **保護対象ファイル保護**: 隔離ディレクトリ内であっても、`.env`、`.git/config`、`.git/hooks` などの改竄や読み出しは即時拒否されます。

---

### 第6層: 野党査問役 ＆ 国家公安・情報漏洩監査役の相互牽制

Naikaku の最大の特徴である**「合議制による相互牽制」**が、情報漏洩に対しても機能します。

- **国家公安・情報漏洩監査（Public Safety & DLP Auditor）**:
  - デジタル執行担当が発行したコマンドをリアルタイム監査。
  - `curl -d @...`、`wget --post-data`、反転シェル（Reverse Shell）、`git push` など、**外部へのデータ持ち出し（Exfiltration）コマンドを検知した瞬間に即座に拒絶（VETO）**。
  - 安全基準違反が 1 件でも発生した場合は、内閣投票で直ちに **`BLOCK`（執行停止）** となり、コードの採用は拒絶されます。
- **野党査問役（Opposition Critic）**:
  - テスト結果や差分（Git Diff）を精査し、不審な外部通信ライブラリの追加やセキュリティ境界の侵害がないかを厳しく追及。

---

### 第7層: 改竄防止セッション受領書と監査証跡（SHA-256 Receipts）

ミッションが完了すると、監査部門や法務への報告に必要な完全な証跡パッケージが自動生成されます：

- **`receipt.json` (セッション受領書)**:
  - 実行日時、担当ロール、判定結果（`verified` / `ship`）、変更ファイル一覧、および各ステップの SHA-256 チェックサムを記録。
- **`git.diff` (Git 統一差分)**:
  - AI が実際に変更したコードの完全な差分。DLP サニタイザーにより機密情報は自動マスキング済み。
- **`evidence.json` (監査エビデンス)**:
  - 実行された全テストコマンド、標準出力、終了コード、野党査問の指摘事項、内閣採決スコアを含む総合パッケージ。

これらにより、「いつ、どのモデルが、どの要件に基づき、どのコードを変更し、安全性がどのように検証されたか」を客観的に証明できます。

## 3. 情シス・セキュリティ監査担当者向け検証手順

Naikaku が組織のセキュリティポリシーに準拠しているか、以下のコマンドで即座に検証できます：

### 1. 公開スコープ・機密情報混入チェック
```bash
npm run public-scope:check
```
リポジトリ内に秘密鍵、環境ファイル、社外秘アセットが混入していないかを全自動スキャンします。

### 2. DLP（情報漏洩防止）単体テストの実行
```bash
npx vitest run src/domain/dataLeakProtection.test.ts
```
AWS キー、GitHub トークン、マイナンバー、クレジットカード番号の検知・マスキング、Worktree 脱出遮断機能が正常に機能していることを検証します。

### 3. 自律目標エンジンの安全監査スモークテスト
```bash
npm run goal:smoke
```
隔離 Worktree 内でのコード生成、実テスト実行、野党査問、公安監査（DLP）、および SHIP 承認（94点）までの全プロセスを 2 秒で体感できます。
